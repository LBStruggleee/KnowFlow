# KnowFlow 产品设计改进文档

> 基于代码审查结果，梳理核心改进方向与功能优先级

---

## 一、核心定位

**目标用户**：大数据课程学习者  
**核心价值**：将分散的课程资料（PPT、PDF、笔记）转化为可对话、可溯源的专业知识库  
**当前阶段**：工程骨架完善，核心体验待优化

---

## 二、核心问题诊断

| 问题 | 影响 | 优先级 |
|------|------|--------|
| 检索质量差 | 无有效 embedding 时，答非所问 | P0 |
| 多轮对话浅 | 只参考上一轮，复杂追问无法处理 | P1 |
| 无流式输出 | 用户等待时间长，体验差 | P1 |
| 无评估体系 | 不知道检索准不准，无法迭代 | P2 |

---

## 三、改进方向与功能

### 方向一：检索质量提升（P0）

**目标**：让"找得准"成为基础能力

| 功能 | 说明 |
|------|------|
| 语义 Embedding | 接入 DashScope text-embedding-v3，确保有有效 API Key 时才启用检索 |
| 多轮查询重构 | 检索时参考最近 3 轮用户问题，而非仅上一轮 |
| Chunk 策略优化 | 支持按标题/段落切分，保留章节结构信息 |
| 混合检索 | 向量检索 + 关键词检索（BM25），提升召回率 |

### 方向二：对话体验升级（P1）

**目标**：让交互更接近 ChatGPT 类应用

| 功能 | 说明 |
|------|------|
| SSE 流式回答 | 逐字输出，减少等待焦虑 |
| 多轮上下文管理 | 自动维护对话历史，支持追问、澄清、对比 |
| 引用溯源增强 | 点击引用源可定位到原文位置（页码/章节） |
| 问题推荐 | 根据知识库内容推荐相关问题，引导学习 |

### 方向三：知识库管理增强（P1）

**目标**：让资料管理更高效

| 功能 | 说明 |
|------|------|
| 批量上传 | 支持多文件/文件夹拖拽上传 |
| 文件夹级知识库 | 按课程/章节自动组织文档 |
| 文档标签 | 自定义标签，支持按标签筛选和检索 |
| 导入历史记录 | 记录每次上传的批次，方便追溯 |

### 方向四：安全与权限（P2）

**目标**：为多用户/公网场景做准备

| 功能 | 说明 |
|------|------|
| 用户认证 | 登录/注册，支持 OAuth（GitHub/微信） |
| 知识库权限 | 私有/共享/公开三种可见性 |
| API Key 管理 | 用户自行配置 embedding/LLM 密钥 |
| 操作审计 | 记录关键操作（删除、修改设置） |

### 方向五：评估与迭代（P2）

**目标**：让产品质量可衡量、可改进

| 功能 | 说明 |
|------|------|
| 评测集管理 | 维护标准问答对，支持批量评测 |
| 检索指标 | Recall@K、MRR、拒答准确率 |
| 用户反馈 | 点赞/点踩，收集坏案例 |
| A/B 测试 | 对比不同 embedding/chunk 策略的效果 |

`

目标：
  - 依赖注入（FastAPI Depends）
  - 服务层接口抽象（便于切换 embedding/LLM）

### 数据层

`
当前：SQLite + Chroma
目标：
  - 保留 SQLite 作为事实数据源
  - Chroma → 可切换为 Milvus/Qdrant（大规模场景）
  - 引入 Redis 缓存（热门查询、会话状态）
`

## 五、实施路线图

### Phase 1：核心体验（2-3 周）

- [ ] 强制语义 Embedding，移除 hashing fallback
- [ ] SSE 流式回答
- [ ] 多轮查询重构（参考最近 3 轮）
- [ ] 前端拆分 App.vue（聊天视图独立）

### Phase 2：功能完善（3-4 周）

- [ ] 批量上传 + 文件夹级知识库
- [ ] 引用溯源增强（定位到原文）
- [ ] 用户认证（邮箱 + OAuth）
- [ ] 基础评测集（20 个问答对）

### Phase 3：规模与评估（4-6 周）

- [ ] 混合检索（向量 + BM25）
- [ ] 异步任务队列
- [ ] 完整评测体系（Recall@K、用户反馈）
- [ ] 知识库权限管理

## 七、风险与权衡

| 风险 | 缓解措施 |
|------|----------|
| Embedding 成本 | 支持本地模型（sentence-transformers）作为备选 |
| 前端重构引入 Bug | 保留旧版本，灰度切换 |
| 流式输出增加复杂度 | 先支持简单流式，后续加中断/重试 |
| 多用户改造范围大 | 先保留单用户模式，认证作为可选插件 |
