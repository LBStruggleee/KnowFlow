# KnowFlow 产品设计改进方案

## 1. 产品定位

KnowFlow 是一个面向大数据课程学习的私有知识库 Agent。它帮助学生把课件、教材、实验指导书和个人笔记整理成可检索、可对话、可复习的课程知识空间。

产品重点不是提供一个通用聊天机器人，而是让用户能够：

- 快速找到课程资料中的知识点；
- 获得有明确出处、可以回查的回答；
- 理解概念之间的关系，而不只是得到一句结论；
- 根据自己的资料生成总结、对比和练习内容；
- 清楚知道资料是否已成功入库、回答是否有足够依据。

## 2. 目标用户与场景

主要用户是正在学习 Hadoop、Spark、Flink、Hive、数据仓库和分布式系统等课程的学生。

核心场景：

1. 课前导入课件和教材，建立课程知识库；
2. 学习中询问概念、原理、区别和使用场景；
3. 实验中查找命令、配置、报错说明和操作步骤；
4. 复习时生成章节总结、知识点对比和练习题；
5. 回看回答引用，定位到原文页码、章节或幻灯片。

## 3. 当前产品的主要问题

- 检索质量不稳定，系统可能基于低相关内容继续回答；
- 文档入库后丢失页码、章节、标题等结构，引用不够专业；
- 用户无法直观看出当前使用的是语义模型还是低质量降级模式；
- 文档处理任务可能卡住，错误状态和恢复路径不够清晰；
- 问答、文档、设置等能力集中在一个页面，学习主线不够突出；
- 当前更接近 RAG 控制台，还没有形成面向课程学习的 Agent 工作流；
- 私有资料是否会发送到云端模型不够透明。

## 4. 产品设计原则

1. **资料优先**：回答必须以用户选定的课程资料为依据。
2. **证据可查**：重要结论应关联到文档、章节、页码或幻灯片。
3. **依据不足就拒答**：不为了完成回答而猜测或补全事实。
4. **过程透明**：展示入库状态、检索范围、模型模式和失败原因。
5. **学习导向**：围绕理解、对比、总结、练习和复习设计功能。
6. **隐私可控**：明确区分本地处理和云端处理，并让用户主动选择。

## 5. 产品信息架构

建议将产品整理为四个一级区域：

| 区域 | 作用 |
| --- | --- |
| 学习助手 | 进行可信问答、总结、对比和练习 |
| 课程知识库 | 管理课程、文档、标签和入库状态 |
| 学习记录 | 查看历史对话、收藏、笔记和错题 |
| 设置 | 配置模型、隐私模式、检索策略和数据管理 |

首页直接进入“学习助手”，知识库管理作为支撑功能，不让管理面板抢占主要学习体验。

## 6. 主要功能

### 6.1 课程知识库

- 按课程创建知识库，例如“大数据基础”“Spark”“数据仓库”；
- 上传 PDF、PPTX、DOCX、Markdown 和文本资料；
- 展示排队、解析、分块、索引、完成和失败等入库阶段；
- 支持失败重试、重新解析、重建索引和重复文件提示；
- 保留章节标题、页码、幻灯片编号、表格和代码块等结构；
- 支持文档标签、启用/停用和按资料范围提问。

### 6.2 可信问答

- 支持普通提问和连续追问；
- 回答中的关键结论使用编号引用；
- 引用卡片显示文档名、章节、页码、相关片段和匹配程度；
- 点击引用可打开原文并定位到对应位置；
- 依据不足时明确拒答，并提示可以补充哪些资料；
- 支持停止生成、重新回答、复制和反馈回答质量。

### 6.3 学习 Agent

第一阶段提供受控的任务类型，不开放无限自主执行：

- **概念讲解**：用适合当前学习阶段的方式解释术语；
- **知识点对比**：对比 Spark RDD、DataFrame、Dataset 等概念；
- **章节总结**：按知识结构归纳指定资料或章节；
- **多文档综合**：从多份资料中整理共同点和差异；
- **练习生成**：基于资料生成选择题、简答题和参考答案；
- **答题批改**：根据课程资料评价用户答案并指出依据；
- **实验辅助**：从实验指导书中整理步骤、参数和常见问题。

每次 Agent 任务都应展示使用了哪些资料、完成了哪些步骤，以及最终结论的引用来源。

### 6.4 学习记录

- 按课程保存历史会话；
- 收藏回答并整理为个人学习笔记；
- 保存生成的练习、作答记录和错题；
- 支持从某条历史记录继续追问；
- 后续可增加知识点掌握状态和复习提醒。

### 6.5 模型与隐私

- 明确显示当前 LLM、Embedding 模型和索引版本；
- 提供“完全本地”和“云端增强”两种处理模式；
- 首次使用云端模型前说明哪些内容会发送给第三方；
- 模型不可用或发生降级时，在问答区域直接提示；
- 支持导出、备份和彻底删除知识库数据。

## 7. 核心使用流程

```text
创建课程知识库
-> 上传课程资料
-> 查看入库进度和解析结果
-> 选择资料范围或整门课程
-> 提问或选择学习任务
-> 查看带引用的回答
-> 收藏为笔记或生成练习
-> 通过反馈持续校准检索效果
```

## 8. 版本规划

### 第一阶段：可信知识库

- 提升文档解析和结构化引用；
- 引入语义与关键词混合检索、重排和可靠拒答；
- 完善入库进度、失败恢复和索引一致性；
- 改造问答页面，突出回答与引用的对应关系；
- 建立基础 RAG 评测集。

### 第二阶段：课程学习助手

- 增加概念讲解、对比、总结、练习和批改任务；
- 增加收藏、笔记和错题记录；
- 支持流式回答、停止生成和反馈闭环；
- 支持按课程、章节和指定文档提问。

### 第三阶段：可长期使用的产品

- 增加用户账号、知识库权限和数据隔离；
- 增加本地/云端隐私模式和数据管理能力；
- 增加可恢复任务队列、备份、审计和运行监控；
- 根据使用数据增加学习进度和个性化复习能力。

## 9. 第一版范围控制

第一版暂不做开放式网页搜索、任意代码执行、复杂多 Agent 协作、社交功能和大型在线课程平台。优先把“导入自己的课程资料并得到可信、可追溯的学习帮助”做好。

## 10. 成功标准

- 用户能够顺利完成上传、入库、提问和回查引用的完整流程；
- 常见课程问题能稳定命中正确资料，低依据问题能够拒答；
- 回答引用可以定位到原文，而不是只展示一个模糊片段；
- 文档处理失败后有明确原因和可执行的恢复入口；
- 用户能在问答之外完成至少一种学习任务，如总结、对比或练习；
- 用户始终知道资料采用本地处理还是会发送到云端。
