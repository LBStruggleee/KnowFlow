# KnowFlow 产品设计改进方案

## 1. 从第一性原理定义产品

学习者使用私有知识库 Agent，不是为了“和模型聊天”，而是为了降低三类成本：

1. **寻找成本**：从分散的课件、教材、实验手册和笔记中找到相关内容。
2. **理解成本**：把原始材料转化为解释、对比、总结和练习。
3. **信任成本**：确认回答是否来自自己的资料，并能回到原文核对。

因此，KnowFlow 的最小完整闭环是：

```text
课程资料进入系统
-> 资料被可靠处理并可检查
-> 用户提出学习问题或任务
-> 系统只基于授权资料回答
-> 每个关键结论都能回查来源
-> 有价值的结果沉淀为会话、笔记、练习或错题
-> 用户可以继续学习或导出自己的数据
```

任何不能改善这条闭环的功能，都不应优先于检索质量、引用质量和失败恢复。

## 2. 产品定位

KnowFlow 是面向大数据课程学习的本地优先私有知识库 Agent。目标用户是学习 Hadoop、Spark、Flink、Hive、数据仓库与分布式系统的学生、自学者和助教。

它不是通用聊天机器人，也不是文档管理后台。它的核心承诺是：

> 基于用户选定的课程资料，提供可追溯、可继续、可沉淀的学习帮助；依据不足时明确拒答。

## 3. V1 目标与边界

### 3.1 本次完整 V1

V1 必须形成单用户本地学习闭环：

- 课程知识库创建、编辑、删除和切换；
- PDF、PPTX、DOCX、Markdown、TXT 上传、处理状态、失败重试和删除；
- 文档内容/分块预览，引用展示文档名和原文位置；
- 普通问答、概念讲解、知识对比、章节总结和练习生成；
- 多轮会话，新建、恢复和删除会话；
- 回答保存为笔记，练习保存并可标记为错题；
- 学习记录按课程、类型和关键词筛选，并可回到原会话；
- 检索参数、回答模型和隐私模式可配置；
- 无云端密钥时提供明确的本地资料摘要回答，不让核心闭环失效；
- 全量数据导出，以及经过二次确认的数据清理；
- 桌面和移动端均可完成上述核心流程。

### 3.2 明确不在 V1

以下能力需要新的安全和运维前提，不以“伪完整”形式塞入本地版：

- 公网多用户、组织空间和细粒度权限；
- Redis/独立 Worker/PostgreSQL 的分布式部署；
- 开放网页搜索、任意代码执行和无限自主 Agent；
- OCR、复杂公式、音视频与扫描件的高精度解析；
- 自动复习计划、通知推送和跨设备同步。

## 4. 设计原则

1. **课程是第一上下文**：所有资料、会话和学习记录都归属于当前课程。
2. **证据先于表达**：先判断有没有足够依据，再生成回答。
3. **状态必须可恢复**：上传、解析、索引、生成失败都提供下一步操作。
4. **学习产物可沉淀**：回答不是终点，笔记、练习和错题才形成长期价值。
5. **隐私边界可见**：明确本地处理、云端增强和实际 Provider 状态。
6. **复杂度渐进暴露**：默认界面服务于学习，高级检索参数放入设置。
7. **移动端不是缩小版桌面**：证据面板、导航和密集列表应变成适合触控的形态。

## 5. 信息架构

| 一级区域 | 用户问题 | 核心功能 |
| --- | --- | --- |
| 学习助手 | “我想理解或练习什么？” | 问答、任务模式、连续追问、引用、保存 |
| 课程知识库 | “系统掌握了哪些资料？” | 课程、上传、处理状态、分块预览、重试 |
| 学习记录 | “我学过什么，接下来做什么？” | 会话、笔记、练习、错题、继续学习 |
| 设置 | “系统如何处理我的资料？” | 隐私、模型、检索、导出与清理 |

默认进入学习助手；管理能力不抢占主要学习路径。

## 6. 核心功能与状态

### 6.1 课程与资料

- 课程支持名称、说明和分类；
- 上传前校验文件类型、大小与空文件；
- 文档状态统一为“处理中、已入库、失败”；
- 失败状态展示原因和重试入口；
- 资料列表支持搜索、状态筛选、删除和分块预览；
- 引用至少包含文档名、chunk/页码/幻灯片位置、原文片段和匹配分数；
- 处理中的资料自动轮询，完成或失败后停止。

### 6.2 学习助手

任务模式：

- 自由提问；
- 概念讲解；
- 知识对比；
- 章节总结；
- 练习生成。

交互要求：

- 首次提问自动创建会话，追问复用会话；
- 回答必须展示引用数量和最高匹配度；
- 依据不足时返回清晰拒答，不伪造引用；
- 云端模型不可用时降级为本地抽取式回答，并明确标识；
- 支持复制、保存为笔记、保存练习和查看检索过程；
- 证据面板在桌面折叠为竖向胶囊，在移动端折叠为横向胶囊。

### 6.3 学习记录

统一展示四类记录：

- **对话**：来自真实会话，可恢复上下文；
- **笔记**：由回答保存或手工创建；
- **练习**：由资料生成后保存；
- **错题**：由练习记录转化，可标记已复习。

支持课程筛选、类型筛选、搜索、查看详情、继续学习和删除。

### 6.4 设置与数据

- 检索候选数、拒答阈值、回答模型、生成温度；
- 隐私模式：完全本地、本地优先、云端增强；
- 展示当前 LLM、Embedding 和向量索引状态；
- 导出课程、资料元数据、会话、消息、学习记录和设置；
- 清理数据必须要求明确确认，不删除应用配置文件。

## 7. 关键流程

### 7.1 首次使用

```text
创建课程 -> 上传资料 -> 等待入库 -> 提问 -> 查看引用 -> 保存笔记
```

### 7.2 复习

```text
打开学习记录 -> 筛选错题/练习 -> 查看来源 -> 继续会话 -> 标记已复习
```

### 7.3 故障恢复

```text
资料处理失败 -> 查看错误 -> 重试
模型不可用 -> 展示本地降级 -> 仍可基于命中片段回答
依据不足 -> 拒答 -> 提示补充资料或调整范围
```

## 8. 界面方向

沿用已确认的 Liquid Glass 工具型界面：

- 玻璃材质只用于导航、工具栏、浮层和交互胶囊；
- 内容区保持高可读的不透明/半透明底色；
- 主色为深绿，蓝色表示引用，琥珀色表示处理中或练习，红色只表示失败/危险；
- 桌面采用“课程导航 + 主任务 + 可折叠证据”的工作台；
- 移动端使用顶部导航、单列内容和横向证据胶囊；
- 所有触控目标至少 44px，错误、空态、加载态和禁用态均可见。

详细视觉令牌见 `frontend/src/demo/brand-spec.md`。

## 9. 成功标准

V1 验收以可执行行为为准：

- 新用户可在 5 分钟内完成“创建课程—上传—提问—查看引用”；
- 没有 API Key 时仍能完成本地资料问答闭环；
- 处理失败的资料无需重新填写课程即可重试；
- 每个引用能显示真实文档名与位置，不只显示内部 ID；
- 会话、笔记、练习和错题刷新页面后仍存在；
- 用户能导出自己的数据，清理操作有二次确认；
- 桌面、平板、手机无页面级横向溢出；
- 后端测试、前端测试、静态检查和生产构建全部通过。

## 10. 后续演进

当 V1 的检索正确率、引用准确率和拒答准确率有稳定评测基线后，再进入：

1. 结构化章节/页码解析与混合检索、Reranker；
2. 可恢复持久任务队列与版本化索引；
3. 用户认证、权限隔离、审计与限流；
4. PostgreSQL/Redis/独立 Worker 部署；
5. 个性化掌握度、复习计划和跨设备同步。
